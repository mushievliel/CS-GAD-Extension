# Reproducing Stage 2 (Implementation B) and the Baseline

This note documents the minimal set of files needed to reproduce the results in
**Chapters 5.4 and 6.3-6.5** of the report: the closer-to-faithful CS-GAD
reconstruction (Implementation B) and the Modell baseline, both on the expanded
dataset.

## Scope: what these reproduce, and what they do not

These scripts reproduce the **results reported in this project** on this dataset.
They do **not** reproduce the original published CS-GAD implementation:

- The authors' method uses the `stellargraph` biased-walk library, which does not
  install on modern Python. Implementation B therefore substitutes the maintained
  `node2vec` library (same algorithm and parameters, not byte-identical).
- On the original data, Implementation B recovers only two of the paper's four
  attacks (see `results/results_implementation_b.txt`); it is a closer-to-faithful
  reconstruction, not a reproduction of the paper's Table 2.

So: running these files yields the numbers reported in Chapters 6.3-6.5, not the
figures from the original paper.

## Dependencies

**`baseline_modell.py`** - runs in any Python 3 environment: `numpy`, `pandas`,
`networkx`, `scikit-learn`. Deterministic (SpectralEmbedding); no seed needed.

**`cs_gad_colab_v2.py`** - additionally needs `gensim` and `node2vec`, which do
not install in the offline environment, so it is run in **Google Colab**.
Reproducible because the libraries are run single-threaded (`workers=1`).

**Data inputs:**
- `Utils/event_category.json` - the authors' category map (Git-LFS object already
  in the repo; run `git lfs pull` to fetch it).
- `Datasets/attack.json` - the original data (Git-LFS object in the repo).
- `cs-gad-submission/data/attack_expanded_labeled.json` - the consolidated
  labelled dataset, regenerated by step 0 below (its per-record labels are also
  already in the repo as `cs-gad-submission/data/record_labels.csv`).

## Execution

The two parts run in different environments and are documented separately.

### Part A - Local (data pipeline + baseline): verified

The data generation pipeline and the baseline run locally in any Python 3
environment and were **verified end-to-end** with the exact commands below. Run
every command **from the `GNN-AnomalyDetection-main/` directory** (the folder that
contains `Datasets/`, `Utils/`, `cs-gad-submission/`, `project/`). With the paths
below, no file paths need editing. First fetch the Git-LFS objects:

```bash
git lfs pull     # materialises Datasets/attack.json and Utils/event_category.json

# 0. Regenerate the consolidated labelled dataset from the existing repo pipeline.
python cs-gad-submission/code/generate_synthetic_attacks.py \
       --input Datasets/attack.json --outdir cs-gad-submission/data
python cs-gad-submission/code/make_labeled.py \
       --data     cs-gad-submission/data/attack_expanded.json \
       --out_json cs-gad-submission/data/attack_expanded_labeled.json \
       --out_csv  cs-gad-submission/data/record_labels.csv
#    -> cs-gad-submission/data/attack_expanded_labeled.json  (107,225 records)

# 1. Baseline (deterministic). Uses the default paths; no arguments needed.
python cs-gad-submission/code/baseline_modell.py
#    -> prints Table 6.6; matches cs-gad-submission/results/results_baseline.txt
```

Steps 0 and 1 above were checked end-to-end from the repo root with these exact
commands, and `results/results_baseline.txt` is the output of step 1.

### Part B - Google Colab (Implementation B): run separately, manual upload

Implementation B needs `gensim` and `node2vec`, which do not install in the
offline environment, so it is **not** run locally. It runs in a Google Colab
notebook, and its input files are uploaded manually. The steps are:

1. Open a new Colab notebook.
2. Install the extra libraries:
   ```
   !pip install gensim node2vec
   ```
3. Upload `code/cs_gad_colab_v2.py` to the notebook (or paste its contents into a
   cell).
4. Upload the **three input files** to the Colab working directory (`/content`),
   using the file picker (the left-hand Files panel, or `files.upload()`). Upload
   them with exactly these names, which are the script's default paths, so no
   path editing is needed:
   - `event_category.json`   (from the repo's `Utils/event_category.json`, after `git lfs pull`)
   - `attack.json`           (from the repo's `Datasets/attack.json`, after `git lfs pull`) - used by the reproduction control
   - `attack_expanded_labeled.json`  (produced by Part A, step 0)
5. Run the script:
   ```
   %run cs_gad_colab_v2.py
   ```
   It prints the reproduction control (Table 6.4) and the expanded-data detection
   across three seeds (Table 6.5).

The saved output of this Colab run is `results/results_implementation_b.txt`.
Because Part B runs in Colab, it was not executed in the local verification of
Part A.

## Reading the baseline ranks (zero-score scenarios)

In `results/results_baseline.txt`, scenarios 1B and 2B have an anomaly score of
0.000. By the baseline's rule a user that accessed every service it used before is
non-anomalous, so it scores zero and ties with every other zero-score user; its
rank is not meaningful. These rows are shown as `n/a (N tie)`, with N the number
of tied users, and are counted as `missed`. The script prints this explanation in
its header, and Table 6.6 of the report shows the rank for these rows as a dash.
